## 1. 執行摘要與里程碑願景 (Executive Summary & Vision)

Triad-Flow 在 **v2.11.0** 成功奠定了以 `ContainerDriver` 為核心的 Patch Jail 容器隔離架構與跨 7 大語言生態系（Python、Rust、Go、C、C++、JS、TS）的修復對齊。然而，在實務高併發審查與多弱點批次修復情境下，每次調度皆啟動冷容器（Cold Container Spawn）造成顯著的啟動延遲（每次執行約 1.5 ~ 3 秒），且單機循序執行無法有效滿足千行級單元、跨檔案與 Monorepo 的審查吞吐量。

**Triad-Flow v2.12 里程碑** 將引領系統邁向高吞吐、低延遲與實體動態反例驗證的三大革新：
1. **容器沙盒熱重載池 (Hot-Reuse Container Pool)**：透過長駐暖機容器池與單元級工作區熱掛載，將單次修復驗證延遲由秒級降至毫秒級（< 150ms）。
2. **分散式異質審查協調器 (Distributed Swarm Orchestrator)**：支援大跨度變更集的依賴感知分塊與多 Agent 節點並行派發，搭配不可篡改的中間數位憑據鏈。
3. **主動式 PoC 反例合成器 (Active PoC Test Synthesizer)**：在 Patch Jail 容器內為待審弱點動態生成重現腳本，將靜態推論升級為具物理證明力的通過/失敗回歸測試。

全架構嚴格維持 **零外部執行時期 npm 依賴 (`"dependencies": {}`)** 與 Node.js 18+ 跨平台規範。

## 2. 核心架構支柱 (Core Architectural Pillars)

### 支柱 1：容器沙盒熱重載與工作區池化架構 (Hot-Reuse Container Pool)
- **架構設計**：
  - 實作 `ContainerSandboxPool`，依語言映像檔（Node、Python、Rust、Go、C/C++）預先啟動長駐容器（Warm Daemons）。
  - 使用 `docker exec` / `podman exec` 多工轉發指令，避免反覆建構/拆卸容器所導致的 I/O 與程序負擔。
- **隔離與還原保證**：
  - 每個任務執行前透過唯讀快照或獨立 Git Worktree 掛載至容器指定路徑，執行完畢後立即清除工作目錄（Workspace Scrubbing）。
  - 容器具備硬性記憶體上限（`--memory 2g`）、CPU 限額（`--cpus 2.0`）與非特權降權機制（`--user 1000:1000`）。
- **生命週期管理**：
  - 註冊程序結束信號處理器（`SIGINT`、`SIGTERM`、`exit`），保證行程結束時零孤兒容器（Zero Orphan Containers）。

### 支柱 2：分散式異質審查協調器 (Distributed Swarm Orchestrator)
- **依賴感知分塊派發 (Dependency-Aware Partitioning)**：
  - 基於 AST 跨檔案符號關聯（Call-Graph & Symbol References）對 PR 變更進行模組聚類，防止割裂相互依賴的函式邊界。
  - 支援多 Worker 並行處理獨立子模組，並將審查結果匯流至中央共識引擎。
- **中間憑據防偽鏈 (Cryptographic Intermediate Receipts)**：
  - 各分散式節點回傳的報告附帶內容雜湊（SHA-256）與時間戳憑證，中央協調器在合成總結報告前逐一驗證簽章與覆蓋完整性。
- **抗震盪降級通道 (Fail-Closed Circuit Breaker)**：
  - 若特定 Worker 逾時或中斷，協調器自動觸發重試或將該子集標記為 `UNINSPECTED_CHUNK`，絕不靜默吞沒或發放未經檢驗的合格權威。

### 支柱 3：主動式 PoC 反例合成器 (Active PoC Test Synthesizer)
- **物理反例驗證 (Executable Counterexample)**：
  - 解決當前審查引擎主要依賴現有測試套件的限制；針對新增程式碼或缺乏測試的弱點路徑，由 Verifier 依弱點類別（如 CWE-22 路徑穿越、CWE-89 SQL 注入、CWE-416 記憶體釋放後使用）在 Patch Jail 容器中合成最小可重現測試（PoC Harness）。
- **修復前後雙向對照 (Differential Verification)**：
  - 修復前（Pre-Patch）：PoC 執行必須觸發預期錯誤或安全阻擋（非零退出碼或攔截異常）。
  - 修復後（Post-Patch）：PoC 執行必須完全通過（Exit 0 且行為符合預期），且既有迴歸測試不得亮紅燈。
- **資產沉澱 (Asset Hardening)**：
  - 驗證通過之 PoC 自動轉換為專案標準迴歸測試，杜絕未來同類型弱點復發。

### 支柱 4：弱點分類感知的動態異質仲裁 (Taxonomy-Aware Quorum Calibration)
- **領域特化模型權重 (Specialized Domain Calibration)**：
  - **底層記憶體安全 (CWE-119, CWE-416, CWE-190)**：優先參考 OpenAI Codex 與靜態語意分析器權重。
  - **業務邏輯、並行競爭與狀態機 (CWE-362, CWE-835, CWE-755)**：提升 Anthropic Claude Code 語意推理權重。
  - **全域架構掃描與跨模組 Monorepo 上下文**：運用 Google Antigravity (AGY) 1M token 廣域上下文捕捉關聯。
- **動態閾值計分 (Dynamic Consensus Scoring)**：
  - 取代傳統僵化的 2/3 二元投票，針對高危險等級模組（Tier 1）引入動態風險係數加權，達成高精準度審查。
