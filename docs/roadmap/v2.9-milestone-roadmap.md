## 1. Executive Summary & Release Vision

The **Triad-Flow v2.9 milestone** represents the transition of Triad-Flow from an isolated diff review engine into a structurally aware, whole-repository context-resolving consensus platform. 

Empirical observations across 50 live open-source pull request reviews in Track D1 (Shadow Dogfooding) demonstrated that frontier LLM quorums fail not because of reasoning deficits, but because of **context starvation**: isolated diff hunks lack definitions for macros, callee signatures, struct layouts, and cross-file invariants. 

Triad-Flow v2.9 addresses this fundamental challenge by embedding a multi-tier symbol resolution pipeline directly into the native Node.js core, maintaining strict zero-runtime-dependency discipline, deterministic budget allocation, and fail-closed security invariants.

## 2. Core Architectural Pillars of v2.9

### Pillar 1: 3-Tier Cross-File Symbol Resolution Engine
Resolves callees, macros, typedefs, and struct definitions without full-repository re-indexing or external language servers:
- **Tier 1 (Same-File AST Enclosures)**: Extracts enclosing functions, methods, classes, and immediate sibling callees within the modified file.
- **Tier 2 (PR ChangeSet Sibling Files)**: Identifies callees defined in other modified or added files within the same pull request changeSet.
- **Tier 3 (Committed Git HEAD Header & Definition Extraction)**:
  - Resolves `#include` headers, imported modules, and macros directly from the exact committed Git object database (`git show <headSha>:<path>`).
  - Employs `ExactHeadLruCache` bounded by both maximum entries and maximum byte weight, providing high-speed in-memory resolution with zero working tree pollution.
  - Resolves multiline signatures, typedef structs, and preprocessor definitions.

### Pillar 2: Standard Library & Built-in Callee Exemption
Prevents context gap inflation and false uncertainty escalations on ubiquitous platform primitives:
- **Exempted Domains**:
  - ISO C99/C11/C23 and POSIX.1-2017 standard library routines (`memcmp`, `memcpy`, `strlen`, `snprintf`, `malloc`, `free`, `errno`, etc.).
  - Node.js runtime globals and core module exports (`Buffer`, `EventEmitter`, `crypto`, `fs`, `path`).
  - Python built-in functions (`len`, `range`, `isinstance`, `enumerate`, `dict`, `list`).
- **Fail-Closed Escalation**: Truly unknown symbols on security-sensitive code paths are formally classified as `UNRESOLVED_SYMBOL`, forcing the verifier to evaluate context sufficiency and escalate to `HUMAN_REVIEW_REQUIRED` if semantic intent cannot be verified.

### Pillar 3: Precision AST & Syntax Hardening
Eliminates parser ambiguity and misclassifications on complex systems code:
- **C Pointer Return Types**: Supports pointer-returning functions (e.g. `unsigned char *func(...)`) as declarations rather than function call invocations.
- **Control Statement Disambiguation**: Enforces `!isControlOrStmt.test(cleanLine)`, preventing `return func(...)` or `throw func(...)` from being parsed as new function declarations.
- **Word-Boundary Token Matching**: Applies strict word-boundary regular expressions (`\b<symbol>\b`) in `extractCandidateCallSymbols` to eliminate substring collisions (e.g. matching `cmp` inside `memcmp`).

### Pillar 4: Pre-Run Oracle Protocol v2 (`PRE_RUN_ORACLE_V2`)
Establishes cryptographic, tamper-proof governance boundaries:
- Requires the exact patch objective, bound CWE, and verification criteria to be immutably recorded (e.g., in an issue comment or signed provenance record) prior to dispatching reviews to frontier models.
- Prevents post-hoc rationalization, model sycophancy, and goal drift.
